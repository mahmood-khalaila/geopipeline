GeoPipeline

A cloud-native geospatial processing platform built as a DevOps project using AWS, Terraform, Docker, CI/CD, PostGIS, GDAL and Kubernetes.

Architecture

GeoJSON Upload → Amazon S3 → AWS Lambda (Docker + GDAL) → Amazon RDS PostgreSQL/PostGIS → MapServer → WMS

GeoJSON files uploaded to a private S3 bucket automatically trigger a containerized Lambda processor. The processor validates the geospatial data using GDAL and application-level validation, then stores the resulting features in a private PostgreSQL/PostGIS database.

A public MapServer EC2 instance reads spatial data from PostGIS and exposes it through WMS. Processing logs are collected in Amazon CloudWatch.

Infrastructure & Security

The AWS infrastructure is provisioned using Terraform inside a dedicated VPC with public and private subnets across multiple Availability Zones. RDS and the processing components remain private, while only required public services are externally reachable. Security Groups, IAM roles, AWS Secrets Manager and VPC endpoints are used to restrict access and protect credentials.

A Windows development workspace is deployed on EC2 and is accessible through RDP only from a configurable IP range.

CI/CD & Containers

GitHub Actions runs automated tests, builds the processing Docker image, authenticates to AWS using OIDC, publishes the image to Amazon ECR and deploys new versions to AWS Lambda.

Kubernetes / GitOps

A local Kubernetes version of the platform was also implemented using Kubernetes, Helm and Argo CD. PostGIS runs as a StatefulSet and GeoPipeline runs as a Kubernetes Job, with deployment state managed through GitOps.

Technology Stack

AWS • Terraform • Docker • Python • GDAL • GeoPandas • PostgreSQL/PostGIS • MapServer • Lambda • S3 • ECR • CloudWatch • GitHub Actions • Kubernetes • Helm • Argo CD
